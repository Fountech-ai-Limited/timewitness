# v0.8

The command line finds the app and enrols with it.

`timewitness enrol`, `timewitness certificate` and `timewitness send` take the app's address from
`--to`, then from the `TIMEWITNESS_APP` setting, then `app.timewitness.dev`. Until this release a
constant said the app was not open, and all three refused it by name, so no binary built before the
app opened could ever have reached it.

Before a machine credential leaves the machine, each of the three asks the route it is about to use
with no credential. Only the app's own refusal, a 401 saying "A machine credential is needed", lets
the credential go. A redirect, a page, a 404 or a 503 is said in words, and in every one of those the
credential stays on the machine.

None of this is on the path of a stamp or a check. A stamp reads the local clock and signs, and
checking a receipt needs nothing of ours. The Action's send step stays off unless a workflow turns
it on, and with it off nothing calls the app.

Signed binaries for Linux, on x86_64 and aarch64, are attached, as they were to `v0.7`. Check them
with `python scripts/the-binaries-are-signed.py --release v0.8 --linux-only`. No macOS or Windows
binary is released, because neither can be signed yet, so on those systems the command line is built
from source.

What TimeWitness cannot prove is in `docs/what-timewitness-cannot-prove.md` at this tag, and it
binds every sentence above.
