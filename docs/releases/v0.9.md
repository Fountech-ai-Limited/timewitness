# v0.9

`timewitness stamp` takes the hash of a file in place of the file, and the Action gives each receipt
a page of its own and prints its address. How a width is worked out, the receipt format and how a
receipt is read are unchanged.

**A stamp over a hash.** `timewitness stamp --digest <sha-256>` stamps a file somebody has already
hashed, where the file is not on the machine that stamps, or is not to be handed over. The hash is
given as exactly 64 hexadecimal characters, and anything else is refused before a key is made or a
source is asked, as `--subject` and `--digest` given together are. The receipt is the one `--subject`
makes for a file with that hash: the payload record is built by one function either way, and every
attestation was always asked for over the hash rather than the file. So it checks with
`timewitness verify --subject` on the file, and nobody reading it can tell which way it was asked
for. A test holds a receipt stamped from a hash to the one stamped from its file byte for byte.

It was written for the app's no-account page, where the visitor's browser hashes the file and the
hash is the one thing sent, so the receipt that comes back checks against the file they kept.

**A page for each receipt.** After the stamp, the Action sends the receipt to the app and prints the
address of its page, timewitness.dev/r/ followed by the receipt's sha-256, in the log and the job
summary. The page runs the verifier timewitness.dev/verify serves on the receipt alone, in the
reader's browser. The new `publish` input says when: `auto`, the default, publishes for a public
repository and never for a private or internal one, or where the event does not say which it is;
`true` publishes anyway and `false` never does. What is sent is the receipt, which carries the hash
of the file and never the file. Nothing in the step can fail the job: a refusal, no answer or an
answer naming another page is a warning, and the address printed is the one worked out from the
receipt's own bytes. A workflow pinned to an earlier tag is untouched.

**Also in it.** The verifier page ships its third-party notices beside it, written from its module
and held to the licences `deny.toml` allows. The README says one step in a workflow file, as the
claim and the Action do. A push of backup refs runs the secret and word scans and nothing else.

Signed binaries for Linux, on x86_64 and aarch64, are attached, as they were to `v0.8.3`. Check them
with `python scripts/the-binaries-are-signed.py --release v0.9 --linux-only`. No macOS or Windows
binary is released, because neither can be signed yet, so on those systems the command line is built
from source.

What TimeWitness cannot prove is in `docs/what-timewitness-cannot-prove.md` at this tag, and it
binds every sentence above.
