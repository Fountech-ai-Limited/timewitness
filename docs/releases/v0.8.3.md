# v0.8.3

The Action takes a new name, and four crates in the lockfile move past seven advisories filed since
`v0.8.2`. How a stamp is taken, how a width is worked out, the receipt format and how a receipt is
read are all unchanged.

**The name.** `action.yml` now names the Action "TimeWitness Receipt". GitHub Marketplace lists an
Action under the name in its manifest, "TimeWitness" is already taken there, and the description the
manifest carried was longer than the 125 characters a listing allows. The description now reads:
"Stamp a release with a receipt: the time, a bound on how wrong it could be, and outside signatures
anyone can check." The inputs, the outputs and what the Action does are as they were at `v0.8.2`,
and a workflow pinned to an earlier tag is untouched.

**The advisories.** The weekly read of the live RustSec database went red on 2026-10-26 on seven
advisories against four crates:

- rustls 0.23.45, four of them, RUSTSEC-2026-0346 to RUSTSEC-2026-0349. It moves to 0.23.46.
- rustls-webpki 0.103.15, RUSTSEC-2026-0382. It moves to 0.103.16.
- webpki-roots 1.0.9, RUSTSEC-2026-0381. It moves to 1.0.11.
- ctutils 0.4.2, RUSTSEC-2026-0385. It moves to 0.4.6.

Each is the first version the advisory names as fixed, or a later patch release of it. No line of
our own code changed with them. The pinned copy of the database the build reads moves to the
revision that was read clean after the upgrade, so the build now sees all seven.

**Also in it.** The limitation list is at version 30, and `timewitness cannot-prove` prints it. A
receipt carries whichever of the three evidence roles were gathered for it, which can be fewer than
three or none, and the item now names the three ways a role is left out: its party was not asked,
gave no usable answer in time, or gave one that was set aside. A test now holds that the wait since
a reading starts after the beacon fetch, so a slow drand relay is never counted as time since the
reading.

Signed binaries for Linux, on x86_64 and aarch64, are attached, as they were to `v0.8.2`. Check them
with `python scripts/the-binaries-are-signed.py --release v0.8.3 --linux-only`. No macOS or Windows
binary is released, because neither can be signed yet, so on those systems the command line is built
from source.

What TimeWitness cannot prove is in `docs/what-timewitness-cannot-prove.md` at this tag, and it
binds every sentence above.
